## Owners (`E00-T01`)

Every epic in the site-facelift program has one accountable owner by role. Named
individuals are assigned by the team; until then the role is the owner of record.

| Area | Owner role | Accountable for |
|---|---|---|
| Positioning and vocabulary | Product marketing lead | Category, message house, claim policy (`E02`, `E03`) |
| Docs operations and IA | Docs lead | Docs structure, onboarding path, operations content (`E05`, `E06`, `E07`) |
| Release quality | Release engineer | Link/placeholder/claim gates, CI, freshness (`E00-T07`, `E12`) |

Each epic's `bw` issue carries its owner role as a label. A name is added to the
role when the team confirms assignment; the role accountability does not wait for it.

## First-run commands and APIs (`E00-T09`)

The site currently exposes two competing onboarding APIs. Differences are listed
here so `E01` and `E05` can converge on one.

| Concern | Legacy `/getting-started` | Current Livebooks / Docs |
|---|---|---|
| Start runtime | `Jido.AgentServer.start(agent: MyApp.WeatherAgent)` | `Jido.start()` then `Jido.start_agent(Jido.default_instance(), MyAgent, ...)` |
| Send work | `MyApp.WeatherAgent.ask(pid, ...)` | `MyAgent.ask_sync(pid, ...)` |
| Await result | `MyApp.WeatherAgent.await(request)` | (folded into `ask_sync`) |
| Install | (narrative) | `mix igniter.install jido` (target for `E05-T06`) |
| First LLM model | `model: :fast` (resolves to Anthropic under an OpenAI key — broken) | explicit provider/model (target for `E01-T01`) |

Canonical target: one API style across home, onboarding, Livebooks, and the
starter (`E05-T24`), using `mix igniter.install jido` and explicit provider/model
on the first LLM request.
